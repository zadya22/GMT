How this platform works

One local database, three views

There is exactly one list of entrepreneurs and one list of coaching sessions behind this entire platform, stored in this browser. Every screen you've seen — coach, entrepreneur, HQ — reads and writes the same records, so within one device there is no duplicate spreadsheet.

No duplicate spreadsheets

A session logged once by a coach is the same session HQ sees on their dashboard — not a copy, not a re-entry.

Locked schema

New fields are only ever added, never replacing old ones, so historical records are never invalidated by a change elsewhere.

Works fully offline

No server, no login system, no internet connection required — everything runs and saves locally in this browser.

The honest limitation: this is one device, not one server

Because this file saves data in this browser's local storage, a coach on one laptop and an HQ manager on another computer will each see their own local copy, not each other's live updates. That's the trade-off of a single, no-install HTML file: full offline independence, but no automatic sync between devices.

To get true multi-device, multi-person syncing — the same record updated by a coach in the field and instantly visible to HQ elsewhere — this front-end would need to connect to a real backend (for example, a small server with a shared database like PostgreSQL or Firebase). The screens, flows, and data model here are already designed for that: the storage layer is isolated in one place in the code, so swapping it for real API calls would not require redesigning the interface.
